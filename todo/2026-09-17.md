# 2026-09-17 — Openstage is born

**Openstage** is the presentation framework extracted from the generic `presenter` template into its own canonical repo. It will live at `present.humanquest.net` and drive the AI Patterns talk (with the other patterns embedded live inside it) at AI Tinkerers Doha Round 3 on Sep 21.

## What We Built

- **Extracted the framework into its own repo.** `presenter` lived inside the `Code` uber-repo with three diverged forks (`cc-presenter` = Cold Club, `tinkerer-presenter` = AI Tinkerers, `cold_club_web`). None was a clean base. This repo is the clean one: routes are only `sample-scroll`, `sample-slides`, `awwwards-flagship`, `showcase-games`, `admin`, `api`, `auth`, `share` — no tenant content.
- **Renamed** package + site metadata from Presenter → Openstage. Added `.env.example` documenting every required variable (values withheld).
- **Excluded from the copy:** `node_modules`, `.next`, `.env.local`, build artifacts. No secrets crossed over.

## Key Decisions

- **The name.** "Deckless" was a campaign line that named the thing we're escaping. What's actually built is a cue-driven live-event system — lobby screen → deck → live hand-off → connect → recap — where the deck is one surface and the audience is an input. *Openstage* = a stage anyone can put software on. It echoes *Tinkerstage*, which becomes "an instance of Openstage." Rejected: Cue (close second), Showrunner and Stagehand (name collisions with Fable Simulation and Browserbase), Mainstage/Backstage (Apple/Spotify).
- **Positioning:** not a deck tool. Every existing deck tool stops at "during" and treats the audience as viewers; Openstage owns before/during/after and treats time and the audience as inputs.
- **Docs are fragmented and must be consolidated.** The rules live in three diverged `CLAUDE.md`s (246 / 394 / 584 lines); the richest — the quality bar and the scroll-deck pitfalls — is `tinkerer-presenter`'s. Consolidating them into one canonical ruleset here is the real extraction work, tracked in `alibad/humanquest#6`.

## What We Built (cont.) — the AI Patterns deck, `/ai-patterns`

The Round 3 talk, built to honour the room's own rule ("demos, not decks"): **three of the four patterns run inside the presentation**, they aren't described.

- **Feedback** — the widget the template already mounts globally is pattern #1; the section tells the room to file a bug *against the page they're looking at*.
- **Openstage** — the deck itself is pattern #2; a `HorizontalPin` "cue sheet" walks the five surfaces (lobby → deck → hand-off → audience input → recap).
- **Walkthrough** — a `StickyMedia` section that reads `/walkthroughs/catalog.json` if a generated artifact is present (feature count flips in), else shows the pipeline honestly as "artifact drops in before the talk".
- **MCP** — a live panel that `GET`s this app's own `/api/mcp`, renders the advertised tool + argument keys, and can `POST` an invocation behind a deliberate two-step arm/confirm (never a page-load side effect; no browser `confirm()`).
- Closes on the meta-pattern — *Workflow · Skill · Domain · Rinse · Repeat* — with a `Spectrum` (library → skill → pattern) and links to the two already-public repos.
- English-only; uses the shared `<ChapterNav>` (not a hand-rolled rail); `w-full` on the Section wrapper per the pitfalls; every number verified in-session (18 skills, 20 walkthrough references, 3 feedback platforms, MCP built 4×, 8 fleet MVPs). Builds clean: `✓ Compiled`, `/ai-patterns` route, no lint/type errors. Registered as `draft`.
