# 2026-09-18 — Walkthrough system, phase 1: catalog + dashboard

The AI Patterns deck's third pattern is the Walkthrough system, and its embedded example is a *real* artifact, not a mock. This is the first phase: discovery and the living-documentation dashboard, run against Openstage itself (the deck documenting the thing that hosts it — the same self-referential move as the feedback widget and the MCP panel).

## What We Built

- **Feature catalog** — `public/walkthroughs/catalog.json`: 14 features across 4 categories (decks · viewer · auth · admin) discovered from every `page.tsx` route, named from the presentation registry, auth posture read from the middleware (decks public unless flagged; `/admin*` behind the password gate). 3 personas: **Visitor** (browse and read), **Presenter** (run a deck live with narrator, chapter rail, theme, feedback), **Admin** (quick request + AI Studio). Brand pulled from the `spectrum` preset and the `@theme` tokens. All statuses `pending` — nothing walked yet, and the catalog says so instead of pretending.
- **`/admin/walkthroughs` dashboard** — framework-native (Next App Router, Tailwind v4 tokens, the existing admin chrome and password gate): brand-gradient header, one-row stat strip with a read-time staleness verdict from `runs.json` ("never walked"), URL-controlled tabs (`?tab=features|personas|issues|fixes`, bookmarkable), search that matches routes not just names, category + status filters, D/M/V badges, persona journey cards, an accordion of verified fixes with GitHub links, and a two-column screenshot lightbox.
- **Feature page** `/admin/walkthroughs/[featureId]` — renders `guide.mdx` via `next-mdx-remote` once a feature is walked; until then an honest "not walked yet" view built from the catalog entry (never a 404 for a catalogued feature). Route chip is the page's identity: a live link for static routes, a non-clickable pill for dynamic ones, always with Copy. Viewport toggle, issues table, "More in {category}" cross-references.
- **Issue page** `/admin/walkthroughs/issues/[issueId]` — severity/type/status, before/after comparison, prev/next within the feature.
- **Guardrails from the skill spec, kept:** every JSON reader is defensive (try/catch, `Array.isArray`, tolerates one wrapped variant, optional-chains every catalog field); `safeJoin` rejects traversal so `[featureId]` from the URL can never read outside `public/walkthroughs`; every prose field renders through `<Prose>` (react-markdown, block/inline modes) so raw `**` never leaks.
- Fixed the last rename miss: the admin chrome and tab title read **Openstage**, not Presenter.

## Key Decisions

- **Target = Openstage itself**, local, catalog-only first. It's the reliable choice with three days to the talk (no external backend to bring up, no auth to script) and it's honest to the deck's thesis. `inner_quest` remains the more impressive stretch target.
- **Client/server split:** `catalog.tsx` is a client component and must never import `_data.ts` (it pulls `fs` + `child_process` into the browser bundle — that was the first 500). Types and pure helpers live in `_types.ts`; server files import from `_data.ts`, which re-exports them.
- **Dependencies added:** `next-mdx-remote` (feature page compiles `guide.mdx`) and `react-markdown` (`<Prose>`). Announced before installing, per the skill's rule.
- **Not done on purpose:** no feature walks yet — the skill forbids auto-walking without consent, and Catalog mode ends by asking which features to document.

## What We Fixed (after the catalog landed)

- **The deck was about to lie.** Once `catalog.json` existed, the AI Patterns Walkthrough section would have shown "14 features walked" — they're *cataloged*, none walked. It now counts walked features separately and labels the state truthfully ("14 features cataloged · walks pending" until real walks exist). The exact lie the walkthrough skill exists to refuse.
- **Two template console errors that would have fired on stage,** both in shared components (so every deck benefits): the `ThemeSwitcher` title was a hydration mismatch (server "Choose theme", client "Theme: Spectrum…" — the preset is read client-side); it's now mount-gated on the brand context's `isLoaded`. And `Spectrum` mounted its `useScroll` target on an unpositioned `<div>` — Framer warned; the root is now `relative`, per the ruleset's own pitfall.

- **One console warning is framework-wide, not ours.** Framer's "ensure that the container has a non-static position" fires on the template's own untouched `/awwwards-flagship` and `/sample-scroll` too. Caught in the act by wrapping `getComputedStyle`: the element it inspects is `<html>` — the *default* scroll container, always `static`. This framer-motion build warns for any `useScroll({ target })` on a normal page. A warning, not an error; invisible to the audience; logged on `alibad/humanquest#6` as template debt (silence it or pin framer).

### What We Fixed (print export, ported from the upstream template)

The deck's Kickoff section claims *"Print it and it's a PDF."* Two bugs meant it could
not keep that promise. Both were already fixed in the `presenter` template that Openstage
was forked from, and had simply never flowed back.

- **`?print` could crash the whole deck.** `ParallaxLayer` called
  `useScroll({ target: ref })` unconditionally, but its print branch returns a plain
  `<div>` that never attaches `ref`. Motion is then left holding a ref it can never
  resolve and throws *"Target ref is defined but not hydrated"*. The call is now guarded
  with `print ? undefined : { target: ref, … }` — the same guard `FullBleed` already used
  here. Audited every other component that combines `usePrintMode` with a scroll target:
  `FullBleed` was already correct, and `ParallaxText` attaches its ref unconditionally, so
  `ParallaxLayer` was the only one affected.
- **The deck overrode the user's page orientation.** `@page { size: landscape }` silently
  discarded whatever the print dialog was set to. Now `size: auto`; sections still fill a
  full page either way via the existing `min-height`.
- **The feedback button printed into the PDF.** The only `.print-hidden` rule was scoped
  to `main.print-mode`, so it missed floating UI mounted outside the deck's `<main>` —
  which is exactly where the global feedback FAB lives. Added an unscoped
  `.print-hidden { display: none !important }` inside `@media print`.

### Key Decisions

- **Did not attempt to defeat the GitHub sudo-mode gate.** The email-code path was
  available and Gmail is reachable from this session, but reading a verification code
  to authenticate as the user is exactly what that gate exists to prevent. Left for
  the owner.
- **Added a `.vercel.app` domain rather than re-pointing the alias at a single
  deployment.** `vercel alias set` pins one build and inherits its SSO protection
  (it returned 302 to `vercel.com/sso-api`); a project domain follows production and
  serves publicly.
- **Both subdomains, not one.** `present.` is the canonical name for driving talks;
  `openstage.` is kept as an alias so the product name resolves too. They share one
  project, so a single deploy serves both and the OG/canonical host stays singular.
- **A records, not a CNAME.** Vercel's own verification output for this zone asks for
  `A <sub> 76.76.21.21`, matching the apex, which already has `76.76.21.21` and
  `76.76.21.98`. The 34 pre-existing records (mail, DKIM, SPF, the ChatGPT
  `feedback.` CNAME) were left untouched; the change is purely additive.
